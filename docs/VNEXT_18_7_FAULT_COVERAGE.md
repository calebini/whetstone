## Authority and meaning of coverage

The [plan's 18.7 acceptance](../IMPLEMENTATION_PLAN.md#187-atomic-promotion-locking-and-recovery), [D8 required qualification](specs/VNEXT_LOCAL_STORAGE_SPEC.md#required-qualification), and [candidate promotion/recovery ordering](specs/CANDIDATE_EDITING_AND_PROMOTION_SPEC.md) control this inventory. Stage 1 proves committed lineage and repairs its mirrors, ending that recovery invocation before Stage 2. Stage 2 preserves the sole eligible next-ordinal claimant, publishes intent → event → snapshot, then conditionally commits the current pointer. Uncertain publication requires fresh ownership and readback. Read-only inspection never repairs.

Coverage levels used below:

- **Storage:** real local adapter, independent of candidate/Reviewer history.
- **Component:** real domain producer with staged or caller-supplied round selectors. Some tests use actual child processes; others inject Python exceptions.
- **Runtime:** `open_verified_run` and production Reviewer/canonical round inputs. Scripted clients remain appropriate; this is not public CLI/scheduler or live-provider qualification.

A fresh process that reads completed artifacts is not a killed-writer test. An `OSError` raised after a successful public method is not proof of the adapter's uncertain-write classification or ownership poisoning. Neither exception tests nor process kills establish physical power-loss behavior. The test index provides exact method names/locations; links below identify their source modules.
