# Verified Phase 2 operator integration v1

This separately pinned internal consumer extends existing D7 operator decisions
and semantic interpretation follow-ups to committed Phase 2 review evidence.
It activates no public mode and changes no retry, budget or authority policy.

The immutable Phase 2 configuration and review request remain part of proposal
preflight, Editor input and independent Verifier context. A semantic follow-up
must reproduce that exact context as well as its original independently admitted
editing plan, current base, source candidate, final rejection and explicit answer.
The answer grants interpretation only. Selection creates a distinct transaction;
it never reopens the parent, runs a client, grants a review pass or marks a profile
clean. Reentry uses the existing D8 answer/admission/selection barriers and stops
after recovery. Decline, missing consent, changed bindings and superseded sources
cannot enable a child. Suites without this pin keep their existing refusal.

Pre-admission operator choices use the existing inventory-bound request/response
contracts. Exact selected evidence is frozen in the canonical Phase 2 round;
no directory order selects consent. Derived work retains the original finding
and passes the ordinary unit preflight. Pending or declined blocking decisions
remain blocked. Descriptor changes require a new job. Candidate registration,
semantic verification and promotion remain separate, fenced operations.

Verified derived-task results do not discharge the broader original finding.
Resolution receipts retain that original debt and reset no corresponding churn
counter. Only directly admitted original findings with verified whole-finding
coverage can be removed. An interpretation answer, decision selection or
candidate promotion alone is not resolution evidence.

Correction failure reporting traverses the original transaction and only its
explicitly selected, independently validated child chain. Preserve original
report locations; child report directories include the exact transaction ID.
Keep earlier reports immutable and supersede their active status when a child is
selected. Report each child Editor/assembly/Verifier/candidate failure separately,
with the failure-time predecessor candidate and current verified base. A later
promotion cannot rewrite historical unresolved findings. Reviewer and signal
reports retain their existing ordering around the correction transactions.

Freeze continuation, arbitrary rejected-plan repair, declaration disagreement
overrides, new rubric policy, generic Phase 2 resume, version maintenance and
external apply-back are not authorized by this integration contract.
