# vnext-seed-initialization-v1

This is the executable seed-only subset required by D7 and slice 18.3. It supplements the candidate leaf without changing the frozen `vnext-contracts-1` suite. It does not specify candidate identity transfer, assembly, registration or promotion fencing.

Seed inputs must already be normalized by the existing `normalize_draft` rule: UTF-8, LF line endings, no trailing horizontal whitespace, and one terminal newline. Admission never normalizes a hash-bound input in place. Raw source bytes may be retained separately with their own source hash. Absolute descriptor locators must use canonical paths within the selected root; output pointers use their equivalent confined logical paths. Host aliases and symlinks below that root are not accepted as alternate artifact names.

The seed scanner uses the qualified bridge exact-line segmentation for ATX headings and backtick/tilde fences. A heading has up to three leading spaces, one to six hashes and whitespace or end of line; optional trailing closing hashes are removed from its display text. Fenced pseudo-headings, escaped headings and four-space indented text are not headings. The first H1 is omitted only from descendants' display-anchor paths, matching existing review-anchor convention. Slugs use lowercase ASCII alphanumerics and hyphens; repeated slugs receive `#2`, `#3`, and so on in preorder. Stable IDs use the independent D6 seed-section formula. Parent identity follows actual heading levels, including the root H1. The published section-map schema requires nonempty heading text, so an empty ATX heading is recognized but cannot be admitted under that schema; it is never silently renamed.

`section_hash` covers the exact heading and its complete subtree up to the next equal-or-shallower heading or EOF. `direct_body_hash` covers bytes after the heading through the next heading or EOF, excluding descendants. Preamble and heading-free documents remain protected by the full seed hash; no synthetic section is invented. The scanner itself preserves raw offsets and line endings, including CRLF and absent terminal newline, so parser fixtures can verify exact-byte behavior independently of normalized-seed admission.

Before claiming a root, validate configuration/selector agreement, the supported suite, descriptor identity, every required input hash, approved MVP scope, authority/invariant consistency, profile names and positive budgets, mode/gate availability, and collisions with root-level output files. Existing `rounds/` artifacts or a root `.vnext-initializing` claim prohibit fresh admission. The first exclusive creation of the empty root `.vnext-initializing` file claims the root and immediately identifies it as vNext, even before `rounds/` exists or CLI-only selectors have been recorded. A competing initializer must fail. Synchronize that marker and the root directory, then create and synchronize `rounds/` and retain its initialization marker. Never remove the root claim on interruption; an initialized root must retain its exact empty marker. All publication uses durable same-directory temporary writes followed by create-if-absent hard-link publication. Existing immutable bytes must match exactly; conflicting files are never truncated. Synchronize published file data and containing directories.

Publish the immutable descriptor, seed map, ordinal-0 history snapshot and byte-identical current pointer, then the exact seed mirror and the `vnext-admission-v1` completion record. The pointer contains no invented candidate, verification, intent or predecessor lineage. The admission record binds the input selection and exact history snapshot. A partial root is preserved and refused, not initialized again. The retained marker also prevents dispatch into a legacy writer before admission completes.

Readback recomputes the map from the seed and descriptor, validates the descriptor and all original input bindings, validates the admission record and seed pointer, compares current pointer/history bytes, and verifies `spec.md`. Missing/stale materializations are reported; slice 18.3 does not advertise repair or generic technical resume. Existing-root reviewer execution uses a nonblocking advisory lock on a retained inode; competing invocation refuses without changing the owner's run state. This is single-host local-filesystem exclusion for the reviewer/seed subflow, not D8 registration/promotion fencing.

The separately published `vnext-selection-v1`, `vnext-capability-v1`, `vnext-admission-v1`, `vnext-review-run-v1`, `vnext-review-receipt-v1` and `vnext-review-decision-request-v1` schemas own runtime configuration/readback envelopes. JSON is canonical except explicitly raw client responses and telemetry. Review receipts bind exact feedback and decision references, canonical issue IDs, clean status and attempts; readback recomputes these claims and checks profile budgets before reporting completion. A completed invocation is replayed read-only. A partial invocation with no completed run record is not silently rerun.

The read-only decision card identifies a concrete choice in Reviewer evidence; it grants no mutation authorization. Its ID is `decision_` plus SHA-256 of canonical JSON `['whetstone-review-decision-v1', complete_request_without_decision_id]`. The initial deterministic trigger recognizes the words/phrases `choose`, `decide`, `whether`, `operator decision`, `weaken`, `supersede`, `remove normative` or `delete normative` in an in-scope finding's claim and recommended change. Other findings remain unresolved review evidence; absence of a trigger does not classify them as editor-fixable. Full mutation classification and operator-response admission remain slice 18.4 obligations. Pending cards cannot be treated as responses by that later workflow without its exact request/effect binding checks.
