# Verified review sequence v1 (unactivated)

This bounded owner connects standard horizontal V Reviewer requests to canonical
round admission. It is outside shipping suites. Existing P/staged consumers retain
their contracts. Runtime sequences require fresh roots without staged rounds, a
pinned sequence algorithm and the v2 exact-base Reviewer journal. Vertical,
focused, closeout, budget extensions, Phase 2, terminal reporting and activation
remain later integration work; unsupported selection modes refuse.

The first review uses the seed pointer. Replay validates consecutive claims and
exact original raw Reviewer evidence against invocation-local proven bases. A
round loader validates only its required complete prefix; it never recursively
proves the current promotion head. A changed base must be the immediately next
committed promotion sourced from the preceding actionable Reviewer round. Same
bytes at different pointer ordinals remain distinct admissions. Findings cannot
be bypassed by a new review on the unchanged base. Rejected or undecided candidates
remain at their existing work/decision boundary; verification alone never advances
the review base. Same-round operator follow-ups retain their original review.

Count completed logical reviews per configured profile across promotions; retries
consume the existing two invocation slots, not another logical round. Select the
first profile lacking clean review evidence, within its pinned budget. All clean
observations are bound to the exact pointer; promotion invalidates them and never
resets budgets. Stop on an exhausted selected profile. `review_complete` and
`budget_exhausted` are local selection observations, not Phase 1 terminals,
convergence or Phase 2 readiness. This bounded owner does not implement soft-budget
sweeps or additional closeout capacity.

New work takes one actual authority fence after committed materialization,
registration recovery and eligible promotion precedence. Pending requests need
explicit technical continuation; retained output/receipts recover without another
client. Immutable root selectors, descriptor, configured role/transport, source
bytes and pointer are revalidated through the existing durable journal.

Canonical round publication derives feedback/advice from the selected completed
Reviewer receipt, constraints from the immutable launch package, and decision
references only from explicit caller selections. Replay verifies those exact
bindings, including packaged constraints. Run shared round preflight, repeat
Reviewer/decision source durability barriers, revalidate, then immutably publish
`rounds/round-N/proposal_input.json`. Reentry must reproduce identical bytes or
refuse a conflict. The producer cannot change original selectors, invent grants,
replace authority, or admit clean-only feedback as an editing round.
