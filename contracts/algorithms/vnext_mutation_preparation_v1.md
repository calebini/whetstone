# vnext-mutation-preparation-v1

This supplement specifies slice 18.4's isolated, non-promoting proposal exercise. Its owner is the candidate leaf's finding-admission and patch-proposal contract. It supplements the frozen `vnext-contracts-1` identities and shapes without changing that suite's bytes or negotiated capabilities. The consuming public proposal runtime must publish a new suite covering these envelopes before activation. Public `proposal_only` and `verified_promotion` remain unavailable at this checkpoint.

## Admission and evidence

The exercise starts at the verified seed, with promotion ordinal zero. Revalidate the descriptor, suite pins, immutable inputs, pinned review configuration, current pointer and byte-identical ordinal-zero history. Reproduce the seed section map from exact seed bytes. This subset cannot admit work against a promoted candidate or infer a current base from materialized `spec.md`.

Reviewer feedback must be schema-valid, hash-bound to that base, and canonical under the existing issue identity and severity rules. Its Reviewer identity and profile must match the pinned configuration. Retain canonical issue IDs and all contributing source feedback IDs and exact Reviewer items. Conflicting recommendations for a repeated issue require a decision; they must not silently overwrite earlier evidence.

`vnext-finding-advice-v1` is optional advisory input. If present, it must cover exactly the source feedback IDs and bind the job, base, feedback reference, authority, scope and invariants. Advice supplies classification, declared authority scopes and bindings, scope surface IDs, requested effects and explicit compatibility intent (`none`, `introduce`, `remove`). It grants no permission. The Orchestrator resolves Reviewer display anchors to existing stable section IDs and validates declared roles and scope coverage; advice cannot invent mutation addresses.

Missing advice or effect information, unresolved targets/scope, inappropriate requirement sources and visible policy/destructive triggers prevent ordinary editor-fixable admission. The deterministic text trigger covers compatibility, migration, legacy aliases, dual-model behavior, weakening, deletion, removal, supersession, choosing/deciding, authority precedence and scope expansion/reduction. These checks do not claim to identify every semantic policy choice. Candidate validation and independent verification remain mandatory downstream gates.

An explicitly deferred scope surface stays excluded, including when its deferred request would be destructive. Deferral need not pause unrelated admitted work. A finding explicitly reporting a blocking invariant violation cannot use deferral to suppress that conflict. Out-of-scope work, forbidden compatibility introduction and mutation of a blocking frozen section require a new immutable job when the active input policy would have to change. An operator response cannot override those input hashes. Removing existing compatibility behavior remains distinct from introducing it and still requires an exact operator decision.

## Operator decisions and plan construction

`vnext-mutation-decision-request-v1` binds the original issue and source feedback IDs, original non-editable classification, exact targets, feedback references, job/base/input hashes and concrete options. Each option declares its authorized effects and deletion-unit IDs. Its ID is `decision_` plus SHA-256 of canonical JSON `['whetstone-mutation-decision-v1', complete_request_without_decision_id]`.

Only an explicitly supplied operator-owned response artifact can select an option. Validate the request's recomputed identity and complete current bindings, then validate the existing `operator-decision-response-v1` response identity, selected option, exact effects/units, deciding actor and rationale. The request hash transitively binds protected invariants. Timestamp exclusion from response identity follows D6; the exact persisted response hash still participates in transaction identity. These records attest authorization provenance, not cryptographic authentication or the semantic truth of an unseen rewrite.

A valid nonempty-effect response creates a distinct derived editor-fixable issue. Its existing canonical issue fingerprint uses type `operator_authorized_task`, exact target IDs, a null invariant, and canonical JSON of `original_finding_id`, `operator_response_id` and `decision_request_hash` as the claim. Preserve the original classification and source evidence. An empty effect list defers the choice and creates no task. Deferring a blocking unresolved choice does not authorize unrelated editing under that same admission.

Mutation constraints are explicit inputs: operation types, maximum operations, maximum changed sections, maximum changed normative units, and required context bindings. No implicit budget or editable-surface expansion is permitted. Add applicable declared normative authorities and the sources of protected assertions to required context; excluded context cannot enter the plan or prompt. Merge admitted findings that share targets into section slices, sort their targets/findings, and derive slice and transaction identities using D6. The slice union is exactly the admitted finding set. No admitted work means no fabricated transaction. The frozen plan has no overlap-authorization field; this version therefore rejects overlapping base mutations even when operation dependencies exist.

Operation-count and declared section-surface caps are checked in preparation. The normative-unit cap is bound in the plan and Editor context; actual changed-unit counts and candidate-wide deterministic assertions require assembled bytes and are enforced by slice 18.5 before candidate eligibility. Passing preparation is not a preservation report. Blocking frozen-section admission checks cannot stand in for those later assertions or semantic verification.

## Proposal transport and normalization

`PatchProposalClient.propose(prompt)` returns exact UTF-8 JSON bytes in `vnext-proposal-response-v1`: a `patch-set-client-v1` shaped patch (wire `schema_version = patch-set-v1`) and inline payloads with exact `path` and `content`. The patch has a null proposal ID and local operation labels. The prompt contains actual admitted source findings, applicable bound operator responses, the plan, target section bytes, input contracts and exactly the declared dependency context. IDs alone are not adequate instructions. No Editor filesystem mutation is part of this protocol.

Retain the prompt and raw returned bytes before parsing. Transport payload paths must be unique and equal the patch's references, with no unrelated, missing, traversing, absolute or symlink payload. Validate UTF-8 bytes and exact hashes; publish canonical content-addressed paths `payloads/{sha256}.md`. The pinned Editor identity replaces the client's identity claim. Compute canonical operation IDs in dependency order, remap local dependencies, then derive the proposal ID. Local labels, payload locators and response-array order grant no authority.

Before publication, reproduce exact base section spans and hashes, reject unknown/retired targets, stale preimages, identity collisions, unsupported operations, attribution outside a section slice, unresolved dependencies and whole-draft responses. Enforce the candidate leaf's payload-root/heading-level rules. A document root cannot be deleted or replaced as a subtree. Multiple insertions at one anchor require explicit ordering dependencies; base mutation overlap is rejected. An admitted finding that is declined requires plan reconciliation, not automatic promotion of a valid subset.

Removal, weakening, authority-change and scope-change claims must cite derived tasks whose responses authorize that effect. A subtree deletion must declare removal and have a null payload. Its exact removed protected unit IDs must be authorized both by the plan and by the responses cited through the operation's addressed tasks; approval for unrelated work cannot be borrowed from the plan-wide union.

For this seed-only exercise, addressable unit IDs use the D6 seed hash, owning stable section ID, scanner kind and same-kind ordinal. Every nonblank exact scanner unit inside a real section is protected. Preamble has no editable section address. This catalog is not a complete candidate inventory, correspondence map, semantic loss detector or post-promotion unit lineage. Those remain the assembly/validation consumer's responsibility.

## Publication and failures

The exercise claims a fresh round under the existing local reviewer/seed exclusion. Revalidate admission under exclusion and again after the client returns, before publishing canonical proposal artifacts. A changed input leaves raw evidence inspectable but cannot create a canonical proposal. Transport exceptions retain failure evidence; incomplete rounds cannot be silently retried or reset. The exercise performs one injected-client call. Native adapters, D7 bounded shape retries and supported continuation belong to the consuming runtime.

Publish immutable `mutation_plan.json`, `mutation_admission.json`, prompt/raw attempts, content-addressed payloads and `proposed_patch.json`. `vnext-mutation-admission-v1` binds source evidence, original findings, derived tasks, decision references, base pointer and plan hash. `vnext-proposal-result-v1` records the canonical proposal reference with `candidate_registered`, `verified` and `promoted` all false. Raw attempts may retain noncanonical bytes; canonical artifacts use the existing canonical JSON rules.

This local exclusion is not D8 registration/promotion qualification. No candidate registration, verification pointer, promotion intent, draft authority, scheduler state, Phase 2 eligibility or external source is advanced by a successful proposal exercise.
