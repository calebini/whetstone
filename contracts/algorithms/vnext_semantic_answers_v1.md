# Semantic interpretation answers v1 (unactivated)

This component records an explicit answer to a concrete semantic authority question after its candidate's final rejection. It does not authorize editing, resolve unrelated rejection causes, select an active response for a new transaction, clear a final decision's historical outstanding IDs, or change either verified pointer. New-transaction admission remains a separate required consumer. Public qualification is unchanged.

The answer consumer requires its own exact pinned algorithm and two closed schemas, in addition to the semantic request/decision/context contracts. It validates every registered candidate chain and the selected candidate's committed final semantic rejection. The candidate must bind the exact reproduced question and completed Verifier receipt. A valid question retained under a reject-dominant policy result may also receive an answer; its original reject verdict remains unchanged. Missing/technical/unverified results and final verified candidates cannot supply answer authority.

Each named alternative's `authority_binding_id` is its stable option ID in this component. The reserved option `decline` is separate from binding IDs and can be produced only by an explicit decline action with no selected binding. Select actions must name exactly one supplied binding. No alternative, actor, rationale or timestamp is inferred from silence or directory contents. The request is reproduced from its original context, named authorities and exact excerpts before option membership is used.

An answer uses the frozen `operator_decision_response_v1` format and existing response identity algorithm. It binds job, raw semantic request hash, base draft hash, authority map and scope. Both authorized-effect lists are empty. These are interpretation records, so the existing effect-bearing derived-task API must not accept them as editing permission. The typed input also binds the exact final candidate decision reference. A different timestamp cannot overwrite a response with the same timestamp-independent identity; exact reentry reuses identical bytes.

The answer receipt binds the raw question, final candidate decision, response and base pointer. Its scope is `interpretation_only_no_editing_or_authority_grant`. Its content hash determines its immutable path. Submitting an answer publishes this receipt but does not select it as active transaction input; downstream work must name an exact receipt reference. Multiple answers can coexist without a latest-wins rule. An explicit decline receipt never enables work.

Artifacts live separately from immutable Verifier output at `<candidate>/operator_answers/<decision_id>/responses/<response_id>.json` and `receipts/answer-<sha256>.json`. The original `<candidate>/semantic_decisions/<decision_id>/request.json` remains unchanged. Older semantic request readers retain their closed output namespace and cannot infer answer support or authority from these new files.

Submission acquires the same local storage writer lock, validates current admission and complete source evidence, and requires the source candidate still to be latest. Before publishing an answer, repeat the source request/report/receipt barriers and both immutable candidate decision/event/snapshot barriers; recheck the current candidate pointer and exact question/decision bytes. Write the response before the answer receipt and validate readback. A response without its receipt is prepared evidence and is not selectable. Exact resubmission finishes an interrupted prefix without clients, new decision ordinals or changed timestamps. Conflicting response bytes, unknown files/questions, missing receipt sources and stale bindings refuse.

Read-only inspection does not lock, write, repair or select an answer. Historical answers remain readable by exact candidate and receipt while their original job/base bindings remain valid; historical readability is not permission to submit a new answer or launch a transaction. Submission against a superseded source candidate refuses. Source input, response and receipt tampering cannot be hidden by final candidate status or a previous terminal report.

The remaining bridge must bind any separately authorized editing effects and a fresh immutable transaction to an explicitly selected answer. It must preserve historical Reviewer classification, source admission and rejected candidate evidence, then rerun both verification layers. This answer component is not a substitute for that bridge and does not complete slice 18.6.
