# Verified standard Phase 2 target matrix v1

Internal opt-in extension requiring exact rubric evidence. Configuration v2
supports the four normative mid/final and strict/permissive target combinations
with the existing standard rubric, horizontal stateful-system profile sequence
and immutable roles. Configuration changes after entry require a new job/root.

The target matrix is evaluated from retained in-scope findings and exact rubric
evidence. Blockers always prevent convergence. Documented ordinary source majors
may remain for mid/permissive only. Mid targets do not invent final-only rubric
obligations; the fixed standard rubric has no explicit mid-target requirement.
Its mid-target catalogue is empty; annotations or rubric-impact claims for
inapplicable requirements are invalid output, not source-severity authority.
Out-of-scope source findings remain reported but cannot select source editing.
Final targets retain unresolved gaps; permissive gap acceptance requires a
separate authorized decision owner and is not granted by this contract. Final
strict forbids unresolved/accepted gaps. Invariants, authority conflicts and
declaration-scoped serious findings remain independent gates.

Every convergence-acceptance request carries a current immutable declaration,
including the first Phase 2 request. Declaration v2 admits an entry-anchored
initial package with no predecessor consumption. Request/consumption v6 bind
that package and retain normal configured step counts. Subsequent packages bind
the current pointer, exact residual counts, rubric and target. A changed count
or stale hash requires actual regenerated bytes and a remaining ordinary review;
unchanged mechanical validity cannot waive Reviewer disagreement.

Convergence is considered after each valid cycle. It requires an accepted
current-lineage declaration and target satisfaction. Final/strict additionally
requires every distinct configured profile clean on that lineage. Other targets
do not inherit this final/strict-only extra requirement. A candidate promotion
invalidates earlier source cleanliness and stale declaration review authority.
Review-only closeout retains its separately bounded eligibility and cannot
override exhausted budgets with residuals. No new automatic edit/retry, public
mode, version maintenance, freeze release or external apply-back is authorized.

Ordinary exhaustion without current-lineage acceptance first publishes a new
current declaration package, after any required verified-resolution receipts.
It then publishes failure-closeout v2 with explicit halt evidence, preserving
the last actual review and current verified pointer. The current declaration's
Reviewer status is not_run when the source changed after that review. Its
TARGET_NOT_REACHED report and state recover through the existing separate
publication/recovery boundary; no extra Reviewer or Editor call is granted.
