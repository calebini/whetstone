# Verified stored run v1 (unactivated)

This consumer reopens an existing physically bound V root from its canonical immutable `inputs/proposal_run.json` locator record. It preserves that record's descriptor, review configuration, seed map, optional launch package and sorted unique staged-round references. The locator record is not capability or draft authority: every operation freshly validates the registered suite, V descriptor and genuine committed lineage through the existing owners. No existing root is upgraded and no public mode is activated.

Resolve a round only when an explicit operation or evidence already under validation names its positive integer round number. Use its canonical `rounds/round-N/proposal_input.json` record, or its explicitly staged reference when the canonical record is absent. If both exist their bytes must match, and staged content must match its pinned hash. Never enumerate round directories to choose work. Cache the resolved hash only within the current history owner, detect subsequent changes, and independently validate the round's closed record, job, exact base, feedback, decisions and preflight when consumed. Unrelated malformed or future round records do not participate in committed-lineage materialization recovery.

Construct fresh work/operator owners for each operation. Promotion's later materialization proof resolves any new committed source round by the same exact-number rule, rather than requiring a caller to append in-memory selectors after every commit. Reopening after process exit reproduces both original and later round inputs from stored records. Altered root locators or consumed round bytes refuse before dependent work.

This boundary supports explicit staged round inputs and already-published canonical input records. The V Reviewer sequence and its normal round-publication producer remain required integration work. Refuse canonical runtime Reviewer feedback and a live review index until that sequence owner is integrated; alternate input paths cannot bypass it. Do not reuse the seed-only Reviewer protocol for promoted bases.

Forward request, registration, verification, interpretation answers, explicit child selection, promotion and recovery to their pinned owners with their existing gates and budgets. Read-only open/status never repairs. Seed/post-commit mirror recovery ends the invocation; no pending candidate or directory listing can select another promotion ordinal. This consumer does not derive scheduler terminals, convergence, Phase 2 readiness or apply-back eligibility.

Qualification requires reopening seed and genuinely promoted roots, executing a later round after reopen without caller-supplied history selectors, unchanged authority on status, exact staged/canonical consistency, source drift refusal, irrelevant future-input exclusion, runtime Reviewer bypass refusal and own-pin/mode refusal. V Reviewer/scheduler integration, D8 audit and complete release qualification remain open before activation.
