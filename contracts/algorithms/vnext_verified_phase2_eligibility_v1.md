# Verified Phase 2 eligibility v1 (unactivated)

This read-only consumer requires its own algorithm pin plus the verified Phase 1
operator/closeout contracts. `VerifiedRun.phase2_eligibility()` inspects the current
standard horizontal V run. It does not admit or execute Phase 2.

Resolve and prove current verified lineage, exact draft and identity map first.
Preserve mirror recovery, registration recovery and promotion precedence. Status
never repairs them. Missing/corrupt committed authority, map, source or review
evidence refuses; cached readiness cannot substitute. Return detached current
pointer, draft/map references and the immutable review-configuration reference.

Inspect the latest registered candidate separately from draft authority. A prepared
decision blocks for recovery; unresolved decision IDs block for operator action;
an unfinished decision blocks for verification; a final rejection blocks; and a
verified-but-unpromoted candidate blocks for promotion. Actual committed pointer
ancestry, never a candidate-local promotion event alone, establishes promotion.
These blockers withhold acceptance and terminal-derived eligibility claims. A later
promoted child may supersede a historical rejected parent under the existing chain
rules; this does not reopen the parent's decision.

Otherwise reproduce Phase 1 closeout and its operator state projection. Phase 1
prerequisites are met only when the review gate is review_complete, every configured
profile has current-pointer clean evidence, global acceptance is established, the
exact report AND closeout evidence are committed/visible, and the derived run-state
reference matches. Report all applicable Phase 1 blockers in that order. Missing
publication, stale cached success, outside-focus global debt, unsupported/staged
review configuration, unresolved findings and technical review continuation cannot
grant readiness. Read-only correspondence does not establish past durability; any
future mutating Phase 2 owner must reacquire the fence, repeat source/closeout/state
barriers and revalidate these predicates against the then-current pointer.

`phase1_prerequisites_met` is explicitly separate from `entry_permitted`.
review-configuration-v1 binds Phase 1 profiles and role identities, but no Phase 2
target, rubric manifest or Phase 2 profile budgets. No legacy defaults, cached
convergence fields or caller-selected paths can fill this missing immutable binding.
This version always reports phase2_configuration_unbound and
phase2_execution_unavailable; entry, generic resume and apply-back permission remain
false even when the Phase 1 prerequisites pass. A later contract must bind and
validate Phase 2 configuration and its consuming capability before granting entry.

The read allocates no request, review, decision, candidate or promotion ordinal,
acquires no writer fence and writes no state, history, declaration or version.
Version promotion cannot use a legacy metadata exception to bypass the V candidate
protocol. No full-draft Phase 2 executor, public CLI dispatch, shipping-suite
qualification or source apply-back is activated by this contract.
