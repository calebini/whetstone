# Local storage kernel implementation notes

Status: unactivated implementation of the [operator-ratified D8 local storage design](../../docs/specs/VNEXT_LOCAL_STORAGE_SPEC.md), recorded on 2026-09-15. The governing contract now incorporates these physical-binding, fresh-root and uncertainty refinements. This document and `vnext_local_storage_binding_v1.schema.json` remain outside a registered shipping consuming suite. Ratification resolves the design choice; the bounded consistency audit and consuming-release qualification remain open. The historical staged D8 audit packet is preserved unchanged and is not evidence that the consolidated contract has been audited.

## Scope and physical binding

`vnext_local_storage` implements a storage kernel for one host, cooperating processes and one canonical physical macOS/local-APFS root. It is not a candidate registry, scheduler, semantic verifier or promotion engine. Other platforms and filesystems fail closed. Filesystem detection uses the local Darwin `statfs` layout, local-mount flag and APFS type; layout size and offsets were checked against the installed SDK. Every opened artifact directory and file stays on the root device and disallows symlink traversal. Arbitrary external concurrent edits, filesystem rollback and moving an active root remain unsupported.

Exclusive fresh-root initialization creates initial byte artifacts, the permanent single-link regular `rounds/.vnext-authority.lock`, then `rounds/authority_storage.json` last. It refuses every existing root, including an empty or partially initialized root. It does not repair an interrupted initialization or upgrade a reviewer-only root. Its caller must validate and provide the complete descriptor, seed and initial authority set before initialization; the kernel checks canonical descriptor bytes, job ID and exact descriptor hash, not the domain's full admission rules.

The storage binding is a closed, canonical `vnext-local-storage-binding-v1` record containing job ID, canonical absolute root path, root device/inode, APFS filesystem identity, retained lock device/inode and byte hash, and immutable descriptor path/hash. This local physical binding is separate from the content-derived job identity. It prevents another process from accepting a byte-identical replacement lock or copied root as the original writer. A copied root remains available to offline artifact inspection; this adapter refuses it as a writer. No relocation or rebinding procedure is supplied.

## Ownership

Acquisition opens the retained lock with close-on-exec and takes a nonblocking exclusive kernel flock. Missing, replaced, symlink, multiply-linked or changed-byte locks refuse. A caller-provided committed-lineage validator executes while exclusion is held; only successful validation yields an opaque token. The domain consumer must actually validate descriptor capabilities, seed and committed history. Passing an empty callback in a primitive test is not domain qualification.

The token is tied to its exact storage object, live lock descriptor, acquiring PID and fresh nonce. Copying, serializing, replaying, reusing a released token or presenting it to a different store cannot authorize a write. Root, filesystem, binding, descriptor and retained lock identity are checked during each publication. A mutex serializes checks, publication and release. Release validates token ownership and closes the descriptor even if later path tampering has made publication invalid. It invalidates the token before closing and never issues `LOCK_UN`.

A process-wide gate serializes descriptor transitions, publication and fork callbacks. Open stores remain in an explicit registry until `close()`; callers must use a context manager or close them. Before a fork, the gate excludes concurrent transitions. The child invalidates tokens, closes inherited root/lock descriptors without unlocking the parent, discards inherited store registrations and resets its process-local mutexes. Existing child references still fail their PID/closed-handle checks. Executed clients inherit no storage descriptor. A paused owner retains exclusion; owner death releases it when its last descriptor closes. There is no lease, expiration, force-unlock or lock-file repair path.

## Publication and uncertainty

Immutable publication writes exact bytes to an exclusive adapter-owned temporary in the destination directory, handles short writes, and performs `fsync` plus `F_FULLFSYNC`. It links the temporary to an absent final name, synchronizes the directory, removes its own temporary name, synchronizes the directory again and fully flushes the published regular inode before acknowledgement. An existing final artifact must be a confined regular file with byte-identical contents; replay repeats the durability barrier. Different bytes never overwrite an immutable artifact.

Conditional pointer replacement requires an immutable snapshot reference and a transition validator. The kernel checks the snapshot's exact hash and canonical JSON, reads the expected old bytes, executes the validator, rechecks ownership and rereads the old bytes before replacing. It atomically renames a synchronized same-directory temporary containing exact snapshot bytes over the pointer, then synchronizes the directory and fully flushes the file. The domain validator must enforce ordinal, ancestry, dependencies and eligibility; the primitive does not infer those from file names or existence. Registration, verification pointers, promotion and materialization must eventually share this one adapter.

`Publication.outcome` is `committed` only after the required barriers. `StorageWriteError.result` distinguishes `not_committed` from `outcome_requires_reconciliation`. A pre-publication failure can leave temporary files or prepared directories but no new final artifact from that attempt. An attempted link/rename with failed acknowledgement or a failed post-publication barrier is uncertain. Cancellation raised inside publication follows the same classification, including `KeyboardInterrupt` after rename. Uncertainty invalidates and releases the token; there is no rollback. Reacquisition must validate the actual authoritative pointer against immutable history and dependencies before further work. A filesystem/process exception is never permission to allocate another ordinal or invoke another model.

Temporary files are not authority. Interrupted names are preserved, and read-only inspection neither removes them nor acquires exclusive ownership. Cleanup is optional later work under ownership. A reader can observe complete new pointer bytes before a writer has acknowledged durability; observation alone does not grant authority to perform a source write.

## Evidence and limits

The isolated kernel tests exercise real competing/paused/killed processes, fork and exec, thread release serialization, conditional replacement, read-only inspection, complete pointer observations, lock/root/descriptor tampering, immutable replay/conflict, confinement, short writes and injected persistence failures. Real process termination immediately before and after pointer rename is followed by locked readback of the actual pointer and its same-ordinal snapshot.

These tests qualify the tested primitive behaviors on the recorded host. They do not establish physical power-loss behavior, cross-host safety, resistance to arbitrary direct writers, complete candidate-chain recovery or public runtime support. Registration/verification/promotion prefix recovery, complete committed-lineage validation, D7 request continuation, descriptor-bound suite publication and the D8 audit remain consuming obligations. Existing legacy and bridge storage paths do not call this module.
