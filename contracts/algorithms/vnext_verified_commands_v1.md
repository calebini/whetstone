# Config-selected verified commands v1

This consumer implements the ratified Q1 command matrix in the coordinating and
scheduler specifications. Registry recognition alone grants no public execution:
the exact suite digest must also appear in the implementation-owned qualification
map, which remains empty until separate release qualification and activation.

Fresh admission consumes a canonical explicit input package outside a nonexistent
destination. Descriptor, review, authority, scope, invariants, source and mutation
limits must agree before D8 initialization. The shared package copier retains exact
inputs; the verified seed validator and VerifiedRun own V admission and reopening.
Neither an edited config nor removed selectors can convert a retained job.

Every mutating command delegates to the existing fenced owner. Read-only status
and dry-run neither acquire authority nor invoke clients. The command-selected
recovery row is rechecked under the every actual D8 fence before owner validation
and mutation. A changed selection ends that invocation without falling through to
fresh work. The sole cross-fence transition is projection of the selected promotion’s own
committed candidate and next ordinal. Owner validation and source barriers still apply.
The guard is invocation-local, process-bound and serialized on its storage instance.

Phase 1 uses its pinned horizontal, vertical or focused sequence. Phase 2 binds
its root-relative canonical configuration and rubric before its separate entry
commit. Required system metadata is a registered, independently verified and
promoted candidate; it never fabricates an Editor invocation. The Phase 2 rubric
Reviewer transport is read-only; it binds the canonical response schema while
passing its separately pinned structural projection to the native provider.

Resume is limited to the finite ratified recovery table. Repair takes precedence
and stops; client continuation spends only the selected request's retained
allowance. Ordinary live commands cannot retry interrupted requests implicitly.
No generic Phase 2 Editor/Verifier continuation, freeze bypass, source write or
new budget is inferred. Explicit Phase 1 budget grants stop before execution.

Operator and semantic inputs use existing closed schemas and original evidence.
Source review returns an envelope; only a non-null canonical assessment file with
its exact digest is an approval subject. Apply/retry require separate explicit
approval and exclusive source access. Historical recovery uses the retained intent
without requiring current fresh-write eligibility and never replaces source bytes.
Legacy, bridge, reviewer-only and proposal-only dispatch retain their protocols.
