# Verified live work v1 (unactivated)

This consumer selects live Editor, registration and Verifier work over genuine V-mode history. It requires the separately pinned verified-history, promotion and materialization consumers. It does not activate a public suite, derive scheduler convergence, perform Phase 2 or apply source changes.

Every operation freshly proves the descriptor, suite and committed lineage under the real local storage fence. Materialization recovery has first precedence: release the initial critical section, repair against fresh current authority under its own fence, and end that invocation. Status performs the corresponding reads without repairs. Registration orphans require a separate explicit recovery that reconciles the registry and ends without a client, verification or promotion. Otherwise reproduce candidate decisions and reconcile next-ordinal promotion preparation. A reserved claimant, or the latest eligible verified candidate, selects promotion work; no Editor or Verifier is invoked by this consumer in that state.

Live transaction input selection requires an explicitly selected immutable round record and, for a same-round semantic follow-up, its exact committed transaction-input reference. Reproduce the original plan and any answer bindings; the selected base-pointer reference must equal the actual current snapshot, including when identical draft bytes occur at different ordinals. A transaction already registered behind a later candidate is superseded. A new transaction may not skip an unfinished latest candidate. Follow-up selection retains its strict earlier-source and latest-candidate rules.

After selection, keep one real fence continuously through the selected durable journal operation. A private borrowed store lets existing producer methods validate and write within that fence without acquiring a second lock or releasing the first. It checks actual token ownership on every operation, cannot replace global authority, and becomes unusable once the invocation ends or ownership is lost. Admission and historical proof objects never escape or survive for reuse across invocations. Historical request reconstruction is read-only; live requests use the unchanged current-base request journal.

Editor and Verifier budgets, exact frozen context, role identity, raw receipts, technical continuation and shape retry remain owned by their existing journals. A completed Editor request is reused without another client. Registration uses its exact completed handoff and returns only committed creation evidence. Verification selects only the latest registered candidate and rechecks its exact current base. Deterministic rejection stops before the Verifier. Final decisions cannot reopen. Prepared verification packages require explicit continuation, recover their existing bytes/timestamp without another client, and end that invocation. Retained semantic output can complete its final decision only on explicit continuation; no result is invented for a technical failure.

Qualification must cover actual live-owner request/registration/verification/promotion journeys on both seed and promoted bases, recovery precedence, older-candidate and stale-base refusal, same-round follow-up routing, explicit continuation, fence loss/process exclusion and readonly status. Runtime selector persistence, V operator writes, scheduler/phase integration, D8 audit and complete release qualification remain separate requirements before activation.
