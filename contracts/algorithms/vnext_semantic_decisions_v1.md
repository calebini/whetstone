# Proposal-only semantic decision commit v1 (unactivated)

This consumer adds the semantic completion transition to the initial proposal decision journal. It requires its own exact pinned algorithm and the completed, independently replayed durable Verifier receipt. It does not infer trust from a semantic report file or change any shipping suite.

The bounded P path uses two decision ordinals: ordinal 1 is the existing deterministic-fail final rejection or deterministic-pass non-final semantic-not-run decision. Only a completed valid semantic result can append ordinal 2, which is final. Technical attempts remain immutable request evidence and leave ordinal 1 unchanged. The candidate leaf permits retaining that non-final attempt while the first incomplete gate is retried; this consumer does not manufacture extra decisions on status, timeout or reentry. Final decisions cannot reopen, so no third decision is valid in this bounded path.

Ordinal 2 binds the exact first decision hash and all candidate/creation/report/map/patch/input hashes. A semantic pass becomes `CANDIDATE_VERIFIED`; reject or operator-decision verdict becomes `CANDIDATE_REJECTED`. Every semantic decision is final and has `promotion_permitted=false` in P. A concrete unanswered request remains in `outstanding_decision_ids`, including when a reject-dominant uncertainty mapping leaves that request as evidence. Its presence cannot change a reject verdict into an operator verdict or authorize new effects.

The second decision's disposition event is event 3, hash-bound to event 2 with the first effective disposition as predecessor. Its source is the exact second decision. The immutable second pointer snapshot binds both targets. Write/revalidate request evidence and report, re-establish the first immutable decision/event/snapshot barriers, write decision 2, event 3 and snapshot 2, then atomically replace the candidate-local pointer with an exact expected-predecessor check. Current draft/seed authority never changes.

Readback validates the complete initial and semantic prefix. Prepared second-decision artifacts remain ineffective while the pointer still binds ordinal 1; they require exact completion, not another decision or model call. Missing or conflicting sources, predecessors, snapshots, gap/duplicate ordinals, unknown later files, changed semantic raw/receipt/report/request evidence and stale pointer targets refuse. Recovery reuses the persisted timestamp and ordinal. A pointer that already binds both new targets proves the semantic decision committed even if its writer lost acknowledgement. Ordinary closeout reentry must preserve and replay that final decision, never downgrade to the initial not-run decision.

Terminal projection uses the commit-bound decision. Prepared targets report verification-commit recovery while showing the prior effective disposition. Final P pass stops with `TARGET_NOT_REACHED` / `vnext_proposal_only_complete`; valid semantic rejection stops with `TARGET_NOT_REACHED` / `vnext_semantic_rejected`; an operator verdict yields `PAUSED_DECISION` / `vnext_operator_decision_required`. These final outcomes are not technical retries. The original deterministic-failure and unavailable-semantic projections remain unchanged for their original paths.

The separate semantic journal and terminal wrapper are internal components. Existing command/run routing must explicitly select this qualified reader before it can consume later ordinals; the initial journal is not silently upgraded by new file presence. Remaining runtime/status integration, semantic operator response/new-transaction routing and complete release qualification must finish before 18.6 is declared complete. Promotion is a later consumer and may append a disposition event, never another verification decision to a final candidate.
