# Explicit bounded Phase 2 repair admission v1

Internal opt-in consumer only. Requires the Phase 2 operator integration and
the existing D7/D8 V candidate owners. No public activation or automatic retry.

An explicit request selects the exact latest registered, finally rejected
candidate on the still-current verified base, its final verification and
Phase 2 request/configuration. Outstanding interpretation decisions prohibit
this route. A repair does not reopen the parent or add a Reviewer credit.

The supported semantic-rejection route selects existing operation IDs and
unresolved whole-finding IDs from the committed Verifier result. Operations
must be dependency-closed, share one operation type and address selected
unresolved findings. Targets, effects, original decisions, complete authority
context and numeric budgets cannot expand. The resulting v2 plan is strictly
narrower than the parent editing scope and has a distinct transaction identity.
If no such plan exists, refuse; never reinterpret a rejection as an answer or
resubmit an unchanged plan. Other rejection classes remain explicit gates.

The immutable admission binds caller identity/rationale/time, parent creation,
final decision, exact source context, selected operations/findings and limits.
Publish the admission before the parent's existing single-child selection
marker. Replay follows that explicit marker, bounds every ancestor by creation
ordinal, and reproduces the plan. Evidence precedes both publication barriers.
Lost acknowledgements reuse exact bytes; read-only context/preview never writes.

New Editor and independent Verifier context retain the exact failure evidence.
Every repair is assembled from the verified base and passes both existing
verification layers before promotion. Original findings omitted from a narrower
transaction remain unresolved. Parent reports retain their immutable history;
selected-child reporting applies to repair and interpretation transactions alike.

Frozen suites and legacy/bridge behavior are unchanged. No final-declaration,
rubric, version-maintenance, freeze-release or source apply-back authority is
introduced by this contract.
